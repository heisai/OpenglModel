# OpenglModel 架构分层设计说明

## 1. 目标

本次重构目标：

1. **把 UI 和引擎解耦**，避免业务逻辑混在窗口代码里。
2. **把引擎按职责分层**，让场景、渲染、几何数据各自独立。
3. **保持当前功能不变**（模型创建、拾取、光照、后处理等），只做结构治理。
4. 让后续功能（如太阳可视化、多光源系统、离屏渲染扩展）更容易落地。

## 3. 分层职责说明

## 3.1 App（应用/UI 层）

职责：

- 处理 Qt 界面、菜单、交互事件。
- 采集参数并转发给引擎（材质、光照、创建/删除模型）。
- 不直接做 OpenGL 资源管理和渲染细节。

关键点：

- `mainwindow`：应用入口界面和菜单行为。
- `CustomOpenglWidget`：承接 Qt 的 OpenGL 生命周期（initialize/resize/paint），并调用 `ManageEngine`。
- `ParaConfigWidget` / `LightEditWidget` / `PropertyEditorWidget`：参数面板。

设计思想：

- 让 UI 只做“输入/展示”，引擎只做“计算/渲染”。
- 后续可替换 UI 技术（例如从 Qt Widgets 到 QML）而不改引擎核心。

---

## 3.2 Engine::Scene（场景编排层）

职责：

- 统一管理场景对象生命周期。
- 协调光照配置、动画更新、拾取、渲染调用顺序。
- 维护全局共享状态（例如主光源轨道参数）。

关键文件：

- `ManageEngine`：当前的场景门面（Facade）。
- `camera`：相机数据与变换工具。

设计思想：

- 把“调度逻辑”集中在 Scene 层，避免分散在每个模型类。
- 当前 `ManageEngine` 是核心聚合点，后续可继续拆成系统化模块（LightSystem / PickingSystem / PostProcessSystem）。

---

## 3.3 Engine::Render（渲染基础层）

职责：

- 管理 Shader 程序、uniform 上传、纹理加载与绑定。
- 维护光源数据结构（`LightConfig`）与 Shader 的数据契约。

关键文件：

- `Shader`：Shader 编译、链接、uniform 设置、光照上传。
- `Texture2D`：纹理加载/释放（OpenGL 上下文安全）。
- `LightConfig`：光源类型、模式、参数。

设计思想：

- Render 层不关心“场景里有谁”，只关心“怎么画、怎么上传 GPU 参数”。
- 这和 Filament / Ogre 的渲染子系统设计一致：数据与渲染接口解耦。

---

## 3.4 Engine::Renderables（可渲染对象层）

职责：

- 封装具体对象的 Draw/InitBufferData 行为。
- 每个对象模块负责自己的顶点布局、材质绑定、绘制路径。

关键文件：

- `Graphics`：可渲染对象基类（共享 MVP、Mesh、材质等）。
- 子目录：`GeneralModel`、`GridModel`、`ShaderModel`、`PlanteModel`、`CubeMapsModel`。
- `common/`：共享 GLSL 片段。

设计思想：

- 采用“基类 + 多态绘制”模式，便于按对象扩展。
- 新增对象时，只需新增一个 Renderable 类并注册到 Scene 工厂映射。

---

## 3.5 Engine::Geometry（几何数据层）

职责：

- 负责 CPU 侧网格数据生成。
- 定义顶点结构、拓扑、模型数据接口。

关键文件：

- `ModelDataInterFace.h`：公共网格数据契约与 `OperatorAction`。
- `*VerticesData.*`：具体形状数据生成。
- `CreatModelData*`：几何数据工厂。

设计思想：

- 几何层不依赖 OpenGL 状态，便于测试和复用。
- 与渲染层分离后，后续可接入模型导入、程序化生成、缓存机制。

---

## 3.6 Common（通用层）

职责：

- 放置跨模块通用能力：路径、文件读取、翻译映射、基础工具。

关键文件：

- `Utils`：路径拼接、Shader include 解析、材质表等。
- `Translator`：多语言映射。
- `OpengHearder.h`：历史聚合头（当前兼容保留）。

设计思想：

- Common 不依赖 App / Scene / Renderables 的业务逻辑。
- 作为“最低层”稳定依赖，减少循环包含。

---

## 4. 模块依赖规则（建议长期遵守）

推荐依赖方向：

```text
App -> Engine::Scene -> Engine::Renderables -> (Engine::Render, Engine::Geometry) -> Common
```

约束：

1. App 不直接操作 OpenGL 细节（只通过 Scene 门面）。
2. Geometry 不依赖 Renderables。
3. Render 不依赖 App。
4. Common 不反向依赖上层模块。

---

## 5. 本次重构中与路径相关的关键调整

1. Shader 资源根目录由 `src/Graphics` 改为 `src/Engine/Renderables`。
2. `Utils::GetProjectRootPath()` 的根路径探测同步更新。
3. `mainwindow.ui` 中自定义控件头路径改为 `../src/App/...`。
4. CMake 去掉了旧 `src/OpenglWidget/...` 的硬编码，避免后续目录变更反复改构建脚本。

---

## 6. 结合开源项目的设计借鉴

- **Hazel**：Editor/UI 与 Runtime 解耦（对应本项目 App 与 Engine 分层）。
- **Ogre**：Renderable 抽象，具体对象独立实现 Draw（对应 Renderables 目录）。
- **Filament**：场景组织与渲染后端分离（对应 Scene 与 Render 分离）。
- **Magnum**：几何数据与 GL 封装分离（对应 Geometry 与 Render 分离）。

本项目当前规模不大，因此采用轻量版分层；保留扩展空间但不过度拆分。

---

## 7. 后续演进建议（不影响当前运行）

1. **命名统一**：`ManageEngine` 可逐步演进为 `SceneEngine`。
2. **拆系统**：从 `ManageEngine` 中拆出 `LightOrbitSystem`、`PickingSystem`、`PostProcessSystem`。
3. **资源目录**：后续可把 shader/texture 进一步外置到 `assets/`，并加入资源清单管理。
4. **删除历史聚合头**：逐步减少 `OpengHearder.h`，改为按需 include，降低编译耦合。

---

## 8. 快速理解调用链（新成员上手）

1. `MainWindow` 创建 `ManageEngine`。
2. `CustomOpenglWidget::paintGL()` 调用 `ManageEngine::paintGl()`。
3. `ManageEngine` 更新主光源参数并遍历 Renderables。
4. 每个 Renderable 绑定 Shader，上传材质与灯光，执行 Draw。
5. 参数面板信号（材质/灯光）通过 App 层转发到 Scene 层，实时生效。

---

## 9. 总结

本次结构从“按历史目录堆叠”演进为“按职责分层”。

- 开发效率：定位问题更快（UI、场景、渲染、几何边界清晰）。
- 维护成本：新增功能改动范围更可控。
- 可扩展性：为太阳可视化、多光源系统、后处理升级打好了结构基础。
