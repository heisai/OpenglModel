# 光照重构与编译修复：修改说明

本文记录本次对话中为光照配置和编译问题所做的修改，以及每项修改的原因。本文是说明文档，不代表这次文档请求修改了代码。

## 一、设计目标

原来的 `LightType`、`LightMode` 定义在 `LightEditWidget` 内，界面信号也还没有连接到引擎。材质 `Material` 描述物体表面，光源则描述场景中的照明，因此没有把这两个属性放进 `Material`，而是建立独立的场景光照配置。

```text
Material：物体表面如何反射光
Light：一盏灯的类型、颜色和类型专属参数
LightConfig：场景的光照模式和光源列表
ManageEngine：持有场景光照配置并在绘制时提供给 Shader
```

## 二、按文件说明修改

### 1. `src\Graphics\LightConfig.h`：新增场景光照数据

- 定义 `Lighting::LightType` 和 `Lighting::LightMode`，不再由界面类定义。
- 定义光源公共属性、衰减参数、方向光、点光、聚光灯参数，以及包含模式和光源列表的 `LightConfig`。
- 使用 `std::variant` 保存一种光源的专属参数，避免一盏灯的类型与参数互相矛盾。
- 默认配置是单光源模式；列表包含第一盏方向光，以及多光源模式使用的预设点光和聚光灯。上限为 8 盏活动光源。

**原因**：使界面、引擎和着色器围绕同一个场景数据模型工作，同时把光源和材质的职责分开。

### 2. `src\OpenglWidget\LightEditWidget.h` 和 `.cpp`：调整界面与数据类型的关系

- 从界面类移出 `LightType`、`LightMode` 的定义，改用 `Lighting` 命名空间中的类型；相应调整 getter 和信号参数。
- 为下拉框条目保存对应的枚举值，读取条目数据，而不是直接把显示顺序当成枚举值。
- 由于原 `.ui` 中两个标签与下拉框的布局位置交叉，在初始化时交换两个标签显示的文字，确保文字与相邻控件含义一致。

**原因**：避免引擎依赖 UI 类，降低下拉框调整顺序带来的风险，并修正界面上类型和模式标签的对应关系。

### 3. `src\OpenglWidget\ParaConfigWidget.h`：调整转发信号的类型

- 将 `sigUpdateLightToEngine` 的参数改为独立的 `Lighting::LightType`、`Lighting::LightMode`。
- 原有 `ParaConfigWidget.cpp` 中从光照编辑器到参数面板的信号转发继续使用，没有在本次重构中新增该连接。

**原因**：使转发接口不再引用 `LightEditWidget` 内部的枚举。

### 4. `src\OpenglWidget\mainwindow.cpp`：接通界面与引擎

- 连接 `ParaConfigWidget::sigUpdateLightToEngine`，调用 `ManageEngine::setLightSettings`。
- 设置变化后请求 OpenGL 窗口重绘。

**原因**：此前信号只转发到参数面板，没有连接到引擎；用户选择光照类型或模式后，画面不会由此更新。

### 5. `src\Graphics\ManageEngine.h` 和 `.cpp`：管理场景光照

- 增加 `light_config_` 和 `setLightSettings`，保存模式并更新第一盏灯的类型；无效枚举值会记录警告。
- 绘制时调用 `Shader::setLights`，把场景光照交给当前模型的着色器。
- 将地板、普通模型、圆环和星球的片元着色器切换到新的场景光照版本。

**原因**：场景光照应由场景统一持有，不能由每个材质或模型分别维护互相冲突的灯光配置。

### 6. `src\Graphics\Shader.h` 和 `.cpp`：上传光源

- 增加 `Shader::setLights(const Lighting::LightConfig&)`。
- 根据单/多光源模式和启用状态，上传光源数量、类型、颜色及类型专属参数；聚光角度在上传时转换为余弦值。
- 超过 8 盏活动光源时记录警告，并只上传上限内的光源。

**原因**：把 C++ 场景数据统一转换成 GLSL uniform，供不同受光渲染路径使用。

### 7. 新增四个 GLSL 文件：共享场景光照计算

| 文件 | 修改及原因 |
|---|---|
| `src\Graphics\common\scene_lighting.glsl` | 定义光源数组和光源方向、衰减、聚光锥、Phong/Blinn-Phong 公共计算，避免每种模型重复实现。 |
| `src\Graphics\common\scene_fragment.frag` | 为普通模型和星球提供共享的多光源片元着色器。 |
| `src\Graphics\ShaderModel\scene_fragment.frag` | 为圆环的 Phong/Blinn 着色路径接入场景光源，同时保留原来的着色子程序和表面处理方式。 |
| `src\Graphics\GridModel\scene_fragment.frag` | 为纹理地板接入场景光源，并保留其 gamma 处理。 |

原有的旧着色器文件没有删除；实际使用的渲染路径在 `ManageEngine.cpp` 中切换到这些新文件。

### 8. 绘制代码：移除各模型写死的光源

- `src\Graphics\ShaderModel\ShaderModel.cpp`、`src\Graphics\GridModel\GridModel.cpp`：移除绘制时写死的旧光源 uniform；圆环继续上传自己的材质，地板继续使用纹理和 gamma 设置。
- `src\Graphics\GeneralModel\GeneralModel.cpp`、`src\Graphics\PlanteModel\PlanetModel.cpp`：移除写死的旧光源 uniform，并将相机位置改为由视图矩阵求逆得到的世界坐标。

**原因**：避免模型各自使用不同硬编码灯光；新光照计算使用世界坐标，相机位置需要与片元位置处于同一坐标空间。

### 9. `CMakeLists.txt`：着色器可见性与增量构建修复

- 将项目中的 shader 文件加入目标，并标记为非编译源码，方便在项目中查看。
- 对 C++、头文件和 UI 文件的 glob 添加 `CONFIGURE_DEPENDS`，让文件集合变化时触发配置检查。
- 在 **MSVC + Ninja** 下，将项目头文件和 UI 文件显式列为 C++ 源文件的对象依赖。

**原因**：实际构建中 Ninja 没有正确记录本地化 MSVC `/showIncludes` 输出的头文件依赖。`ParaConfigWidget.cpp.obj` 因此仍引用旧的嵌套枚举，链接时出现 `LNK2019` / `LNK1120`。显式依赖能在项目头文件或 UI 改变后触发重编译；代价是可能比精确依赖跟踪编译更多文件。

### 10. `Doc\光照配置设计.md`：新增设计说明

记录了类关系图、光照更新流程、当前能力、优缺点和后续扩展方向。

## 三、实际数据流

```text
LightEditWidget 选择类型或模式
	-> ParaConfigWidget 转发信号
	-> MainWindow 调用 ManageEngine 并请求重绘
	-> ManageEngine 更新场景光照配置
	-> Shader::setLights 上传有效光源
	-> 对应片元着色器逐灯计算并累加
```

单光源模式固定使用列表第一盏灯；如果它被禁用，则不使用其他灯作为替代。多光源模式使用列表中所有已启用的灯。当前界面只能修改第一盏灯的类型，不能增删灯或编辑详细参数。切换模式不会删除其他预设灯；切换类型会重置第一盏灯的类型专属参数，但保留公共颜色。

## 四、影响与限制

- 模型、地板和星球共用场景光源；天空盒、坐标轴和屏幕后处理不参与这套光照。
- 默认场景由各模型原来的硬编码光源改为统一方向光，因此画面可能与修改前不同。多光源的环境光会逐灯累加，也可能更亮。
- 当前没有光源 ID、光源增删界面、详细参数编辑和序列化。以后添加这些功能时，需要对灯数、向量、衰减和聚光角度进行输入校验，并处理超出 GPU 上限的情况。
- 当前逐模型、逐 uniform 上传，灯或模型很多时性能有限；后续可考虑 UBO/SSBO 批量上传。
- `Material` 和 `src\OpenglWidget\LightEditWidget.ui` 未因本次重构而修改；光照编辑器、面板转发、翻译文件及其他工作区改动在开始本次重构前已存在，不应全部归因于本次修改。

## 五、此前的验证记录

- 光照重构时，隔离副本完整构建通过；离屏 OpenGL 测试验证了四个 shader 程序链接、三种光源、零/单/多光源和聚光方向，并验证了实际 uniform 上传。
- Qt 集成测试验证了界面信号经引擎到 GPU uniform 的传递。上述验证程序是临时工具，完成后已清理，不是仓库内持久测试。
- 修复链接错误后，Visual Studio 工作区构建成功；隔离副本中的增量验证确认修改 `LightEditWidget.h` 会重新编译 `ParaConfigWidget.cpp`。
- 构建会执行项目已有的 Qt 翻译生成步骤。本文档请求没有重新构建或修改代码。
